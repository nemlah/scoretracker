# Goalkeeper stats Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Mark goalies in the roster, record their saves, penalty saves and goalie swaps on the Live screen, attribute opponent goals to the goalie in goal, and show per-goalie save % on the viewer (game and season). Also hide empty "(0 – 0 pen.)" shootout lines on the viewer.

**Architecture:** Three new event types (`save`, `penSave`, `gkIn`) go into the game's `events` array. A new self-contained pure module, `js/goalies.js`, replays a game into per-goalie stats and the current goalie in goal. The goalie flag flows roster → selection → lineup and is written back like caps. The tracker tiles, the Events sheet pickers, the viewer tables and the season aggregation all read the replay.

**Tech Stack:** Plain HTML/CSS/JS ES modules (no build), Firestore Web SDK 12.19.0, `node --test`, Playwright e2e against the Firestore/Auth emulators.

**Spec:** `docs/superpowers/specs/2026-11-15-goalies-design.md`

## Global Constraints

- Event objects keep exactly `{ id, type, period, ts, playerId? }`.
- New event types `'save' | 'penSave' | 'gkIn'` are added to `EVENT_TYPES` in `js/model.js`, because the journal rejects unknown types.
- A goalie is a lineup entry with `goalie: true`. A game with no lineup goalie has no goalie stats at all.
- The goalie with the lowest cap starts in goal. `save`, `penSave` and `gkIn` put their `playerId` in goal.
- Save % = (saves + penSaves) ÷ (saves + penSaves + goalsAgainst), counting periods 1–4 only. With no shots faced it shows "—". Round with `Math.round`.
- Shootout (`'SO'`): `penSave` counts as a shootout save and `oppGoal` as a shootout goal conceded. Neither enters save %.
- `js/goalies.js` imports nothing. That keeps the viewer working when a phone mixes old cached and new modules. In `js/viewer.js`, use functions added to `model.js`/`strings.js` on this branch only through the namespace import with a fallback, which is the existing pattern.
- Every visible string lives in `js/strings.js`, and the copy below is exact. Every new JS file goes into `SHELL` in `sw.js`.
- Live tiles never move when the goalie in goal changes. Goalie tiles come first by cap, then field players by cap. SAVE is the largest target on a goalie tile, and every target is at least 48 px.
- Commands:
  - unit: `npm test`;
  - emulator: `PATH=/opt/homebrew/opt/openjdk@21/bin:$PATH npm run test:emu`;
  - focused e2e: `PATH=/opt/homebrew/opt/openjdk@21/bin:$PATH npx firebase emulators:exec --only firestore,auth --project demo-scoretracker "playwright test <file>"`;
  - full e2e: `PATH=/opt/homebrew/opt/openjdk@21/bin:$PATH npm run test:e2e`.
- Deploy only when no game is live.

## Review Focus

1. **A goalie tick changed while a game is live.** The lineup sheet adds or removes a goalie mid-game. Expected: tiles re-sort once, the in-goal default recomputes, and existing goalie events still count for that player. → Task 1 test `events for a player no longer marked goalie still count`; Task 3 test `the lineup sheet can mark a goalie and writes it back to the roster`.

3. **Undoing a `gkIn`.** Expected: the previous goalie is back in goal. → Task 1 test `removing a gkIn restores the previous goalie`.
4. **Old games and old stats docs** (ΡΟΗ, Delfin; no goalies; stats without `goalies`). Expected: they render as today, apart from the shootout-line fix. → Task 6 test `games and stats without goalies render as before`.

### Task 1: Goalie replay, goalie flag flow, season goalie totals

**Files:**
- Create: `js/goalies.js`, `tests/unit/goalies.test.js`
- Modify: `js/model.js` (`EVENT_TYPES`, `defaultSelection`, `lineupFrom`, `rosterWithCaps`, `aggregateSeason`, typedefs), `sw.js` (`SHELL`)
- Test: `tests/unit/model.game.test.js`, `tests/unit/model.season.test.js`, `tests/unit/journal.test.js`

**Interfaces (produced):**
- `js/goalies.js` (no imports):
  - `goalieStats(game) → { goalies: GoalieLine[], inGoal: string | null } | null`. It returns `null` when `game.lineup` has no `goalie: true` entry.
    - `GoalieLine = { playerId, name, cap, saves, penSaves, goalsAgainst, soSaves, soConceded }`, ordered by cap. It includes every lineup goalie, plus any non-goalie `playerId` that has goalie events.
    - `inGoal` is the goalie in goal after the last event.
  - `savePct(line) → number | null`, a whole-number percentage, or `null` when no shots were faced.
  - `inGoalAt(game, eventId) → string | null` gives the goalie in goal when that event is processed.
  - `inGoalSwitch(game, oppGoalId, goalieId, id = crypto.randomUUID()) → { op: 'add'|'remove'|'replace', event, newEvent? } | null`, following the spec's "In goal picker" rules:
    - if `goalieId` is already in goal for that goal: `null`;
    - else, if a `gkIn` exists at `ts === oppGoal.ts - 1` in the same period, and `goalieId` equals the goalie in goal just before it: `{ op:'remove', event: thatGkIn }`;
    - else, if that `gkIn` exists: `{ op:'replace', event: thatGkIn, newEvent: { ...thatGkIn, playerId: goalieId } }`;
    - otherwise: `{ op:'add', event: { id, type:'gkIn', period: oppGoal.period, ts: oppGoal.ts - 1, playerId: goalieId } }`;
    - `null` also when the game has no goalies, the goal isn't found, or `goalieId` isn't a lineup goalie.
- `js/model.js`:
  - `EVENT_TYPES` gains `'save'`, `'penSave'` and `'gkIn'`.
  - `defaultSelection` entries carry `goalie: roster.goalie === true`.
  - `lineupFrom` keeps `goalie: true` only on goalie entries, so other entries keep today's exact shape `{ playerId, name, cap }`.
  - `rosterWithCaps(roster, lineup)` also sets each lineup player's roster `goalie` to `lineupEntry.goalie === true`.
  - `aggregateSeason` gains `goalies: { [playerId]: { name, games, saves, penSaves, goalsAgainst } }`, summed over final games where `goalieStats` isn't null. `games` counts the games in which the player was a lineup goalie.
