# E2E speed: hermetic network, per-worker emulator projects, parallel workers

**Goal:** cut the full e2e run from 18.8 min (serial, measured 20/11/2026) to about 5 min without adding flakes. A throwaway prototype measured 4.7 min with 3 workers.

**Spec:** none (owner-approved investigation, 20/11/2026). Evidence lives in the session-log entry "Why e2e takes ~19 min" and in memory `e2e-speed`.

**Branch:** `e2e-speed` in `.worktrees/e2e-speed`. `node_modules` is a symlink to the main checkout. The fonts in `tests/fixtures/fonts/` are already downloaded: `sofia.css` (served CSS, Chrome UA) plus 10 woff2 files named after their gstatic basenames.

## Global Constraints

- **Production behaviour must not change.** The app may read a test hook only inside the emulator branch: `useEmulator()` is true only on localhost with `?emulator=1`.
- **Mixed module cache rule:** no new named imports of new exports in `js/`. `js/config.js` keeps the same exports.
- **Who runs what:** Codex cannot bind ports or commit here, and the controller runs the emulator and e2e suites. Implementers run `npm test` (unit) and `npx playwright test --list` (parses every spec and the config with no server). Leave changes uncommitted.
- **No new `waitForTimeout`.** Use `expect.poll` or web-first assertions.
- **Focused e2e command** (controller): `PATH=/opt/homebrew/opt/openjdk@21/bin:$PATH npx firebase emulators:exec --only firestore,auth --project demo-scoretracker "playwright test <files> --reporter=list"`.
- **Flake waiver** (memory `e2e-known-flakes`) applies unchanged. Any failure off that list blocks.

## Task 1: Fix the withTwoDevices race and name lost-connection resources

Files: `tests/e2e/tracker-access.spec.js`, `tests/e2e/offline.spec.js`, `tests/e2e/tracker-look.spec.js`, `tests/e2e/tracker-helpers.js`, a new pure module (e.g. `tests/e2e/network-noise.js`, no Playwright import), and a new unit test in `tests/unit/`.

1. In `withTwoDevices` (tracker-access.spec.js, about line 82), the holder is read once right after unlock: `const aUid = await activeUid(); expect(aUid).toBeTruthy();`. Under load the control write has not landed yet, so it reads `undefined` (seen 20/11/2026 on webkit :242 and :310). Poll until it is truthy with `await expect.poll(activeUid).toBeTruthy()`, then read the value.
2. "B took over" polls must require a non-empty holder that differs from A's captured UID. `not.toBe(aUid)` alone accepts an absent holder, and a poll before A's UID is captured accepts A's own holder. This covers tracker-access.spec.js about :91, and offline.spec.js about :216, :269 and :391.
3. Audit the rest of tracker-access.spec.js for the same pattern: one read of server state (`activeUid()`, `get(...)`) right after an action that writes it, with no wait in between. Poll those too. A read after an explicit wait for that state, e.g. `knowsOtherHolds`, is fine; leave it. Don't change what any test asserts.
4. In `collectProblems` (tracker-helpers.js), WebKit's console error `Failed to load resource: The network connection was lost.` must name its resource. For console errors whose text starts with `Failed to load resource`, append ` <url>` from `message.location().url` to the recorded problem string.
   - Build the problem string in one exported formatter.
   - tracker-look.spec.js about :242 and :297 remove errors by exact string. Make them use the shared formatter, or match by prefix, and splice only when the index is found, never `splice(-1, 1)`.
5. In the same function, drop exactly that lost-connection message only when its location URL is a Firestore WebChannel on the emulator: `http://${EMULATOR.host}:${EMULATOR.firestorePort}/google.firestore.v1.Firestore/(Listen|Write)/channel…` (import `EMULATOR` from `../../js/config.js`). The SDK reopens that channel itself, and the tests assert server state. Auth URLs, the static server and failures with no URL stay recorded.
6. Keep every other console error recorded. Grep the specs for assertions on specific problem strings and keep them passing.
7. Put the filter decision in the pure module (e.g. `isFirestoreChannelLoss(text, url)`). Unit-test it in `tests/unit/` with `node --test`:
   - Firestore Listen channel URL → dropped;
   - Write channel URL → dropped;
   - Auth emulator URL → kept;
   - static server `:4173` URL → kept;
   - empty URL → kept;
   - different text → kept.

## Task 2: Hermetic network fixture for every browser context

Files: new `tests/e2e/fixtures.js`; the import line of all 18 `tests/e2e/*.spec.js`; new `tests/fixtures/fonts/README.md`. The fonts themselves are already present.

1. **Shared fixture.** `tests/e2e/fixtures.js` exports `test` (extending `@playwright/test`) and re-exports `expect`. Every spec imports `test, expect` from `./fixtures.js` instead of `@playwright/test`; only that import line changes. Helper modules that import just `expect` may stay as they are.
2. **Every context is prepared.** Each browser context passes through one `prepareContext(context)`: the default `context` fixture, and every context a test makes with `browser.newContext(...)`. There are about 10 such calls, in offline, tracker-access, tracker-live and tracker-events.
   - Cover future calls automatically with a worker-scoped auto fixture that wraps `browser.newContext`. It must preserve `this` and the options, await preparation, and restore the method at teardown. In Playwright 1.64.1, the default `context` fixture also calls `browser.newContext()` when context reuse is off, and it is off here. Verify that in `node_modules/playwright/lib`.
   - A context must not be prepared twice; use a WeakSet.
   - **Per-test diagnostics:** a test-scoped auto fixture owns a problem list for the running test, and every context's handlers write to it. Missing font files, an SDK version mismatch and unexpected external requests are each aborted and recorded. At teardown the fixture fails the test with the list.
3. **Routes in `prepareContext`:**
   - **Firebase SDK:** `https://www.gstatic.com/firebasejs/<v>/firebase-(app|auth|firestore).js` is fulfilled from `node_modules/firebase/firebase-<m>.js` (`text/javascript`). If `<v>` differs from `node_modules/firebase/package.json`'s version, the test fails with a message naming both versions. Never serve a mismatched SDK.
   - **Fonts CSS:** `https://fonts.googleapis.com/css2?…` is fulfilled with `tests/fixtures/fonts/sofia.css` (`text/css`).
   - **Font files:** `https://fonts.gstatic.com/s/**/<name>.woff2` is fulfilled from `tests/fixtures/fonts/<name>.woff2` (`font/woff2`, `access-control-allow-origin: *`). A missing file fails the test with its name. Never serve an empty font: the look specs wait on `document.fonts.check` for Sofia.
   - **`apis.google.com`:** the plan review found that on mobile, Safari or iOS user agents (the webkit project's iPhone 15), `getAuth()` proactively loads gapi, and auth initialisation awaits it. Anonymous sign-in awaits that initialisation in turn.
     - Fulfil `https://apis.google.com/js/api.js?…` with 200 `text/javascript`. The script sets `globalThis.gapi = {}` and calls the global function named by the request's `onload` query parameter, so the SDK's loader settles at once. The SDK catches the resulting rejection and goes on with no console error.
     - Confirm this in `node_modules/firebase/firebase-auth.js`, and explain it in a comment at the stub.
   - **Service worker on WebKit:** `context.route` sees requests that a service worker makes only in Chromium.
     - In the webkit project only, set `serviceWorkers: 'block'` in `playwright.config.js`, but only if both of these hold:
       (a) no webkit-run test depends on the service worker (grep the specs for `serviceWorker`, `sw.js`, `controller`);
       (b) a blocked registration in `js/sw-register.js` logs no console error.
     - If either fails, leave the service worker on. Note in a comment in fixtures.js that WebKit's service-worker fetches bypass routing, and report it.
     - Chromium keeps the real service worker; offline.spec needs it.
   - **Out of scope:** the `<link rel="preconnect">` hints. They open connections but fetch nothing.
   - **Guard:** any other request to a host that is not `127.0.0.1` or `localhost` is aborted. Record its URL, and fail the test at fixture teardown with the list of unexpected external URLs.
4. **offline.spec.js** already routes Google Fonts itself (`FONT_STYLES`) and observes font requests. Its own routes are registered later, so they take precedence. Keep its tests' intent: don't remove its stubs, and make sure the guard doesn't trip on its routes.
5. **Fonts README:** `tests/fixtures/fonts/README.md` gives:
   - the source URL (the css2 URL above, fetched with a Chrome UA on 20/11/2026);
   - the copyright line "Copyright 2019 The Sofia Sans Project Authors (https://github.com/lettersoup/Sofia-Sans)";
   - the licence: SIL Open Font License 1.1, with its full text in `tests/fixtures/fonts/OFL.txt`, which is already present;
   - how to refresh the files if the CSS URL in `index.html`/`track.html` changes.

Done when: `npm test` passes, and `npx playwright test --list` lists the same number of tests as before. The controller then runs the full e2e suite serially.

## Task 3: Per-worker emulator projects and parallel workers

Files: `firebase.json`, `js/firebase.js`, `tests/e2e/helpers.js`, `tests/e2e/fixtures.js`, `playwright.config.js`, `README.md` (test section). `js/config.js` stays unchanged.

1. **Emulator:** in `firebase.json`, set `"singleProjectMode": false`, so the Firestore emulator accepts a project per worker.
2. **One source of truth.** `tests/e2e/fixtures.js` (or helpers.js; one place only) exports `e2eProjectId()`, which returns `demo-scoretracker-${process.env.TEST_PARALLEL_INDEX ?? 0}`.
3. **Firestore is per worker; Auth stays shared.** `tests/e2e/helpers.js` uses `e2eProjectId()` for `initializeTestEnvironment`, which covers seeding, `clearFirestore` and the per-project rules upload.
   - The Auth emulator puts browser sign-ins in the CLI's default project whatever the client's projectId (firebase-tools `lib/emulator/auth/server.js`), so Auth is shared by all workers.
   - **Ruling:** `resetAll` stops deleting Auth accounts. In the shared project, a reset by one worker would delete other workers' live anonymous users, and the SDK signs those devices out when it reloads. Anonymous UIDs are unique per browser context, and the emulator starts empty on every `emulators:exec`. Say this in a comment at `resetAll`.
   - Grep the e2e specs for anything that relies on accounts being wiped between tests, and report it.
4. **App side, emulator branch only:** in `js/firebase.js`'s `initFirebase`, the emulator config becomes `{ projectId: globalThis.__E2E_PROJECT_ID ?? EMULATOR.projectId, apiKey: 'demo' }`. `js/config.js` stays unchanged, and nothing outside the emulator branch reads the global.
   - `prepareContext` sets the global with `context.addInitScript` before any page script runs, using the same `e2eProjectId()`.
   - Without the global (`npm run dev`, `scripts/seed-emulator.mjs`, the emulator suite), nothing changes.
5. **Workers:** `playwright.config.js` sets `workers: Number(process.env.PW_WORKERS) || 3`. `PW_WORKERS=1` gives the old serial run for debugging flakes.
6. **README:** the test section says e2e runs on 3 workers, each with its own emulator project, and notes `PW_WORKERS=1` for serial runs.

Done when: `npm test` and `npx playwright test --list` pass. The controller then runs the full suite with 3 workers (and with `PW_WORKERS=1` once), and the result must pass under the flake waiver.

## Task 1b: Seed-after-start races in the situations and goalies specs

Added during execution (ledger, 20/11/2026). With faster page loads, `tracker-situations.spec.js:198` ("read-only device cannot use PEN or the situation button") failed on webkit in a full run, and the file flaked when run alone (1 of 5 runs). The test calls `startGame(page)` and then at once `seed('control/tracker', { activeUid: 'another-device' })`. If the app's own control write lands on the server after the seed, it overwrites the seed and the takeover banner never appears. The waived tests in these files (situations :133 and :239; goalies :246, :302, :307 and :540) are the same "timing race" family.

Files: `tests/e2e/tracker-situations.spec.js`, `tests/e2e/tracker-goalies.spec.js`, and their shared helpers (e.g. `startGame` in `tests/e2e/tracker-helpers.js`) if the fix belongs there.

1. Find every place in these two specs, and in the helpers they use, where the test writes server state (`seed`, `update`, `remove`) that the app may also be writing at that moment. That means right after an app action whose write may still be pending, such as starting a game, unlocking or taking control. Make the test wait first, by polling the server with `get(...)`, until the app's own write has landed: e.g. `control/tracker` has the page's holder, or the game doc exists with the expected state. Then write.
   - If one helper (e.g. `startGame`) is the common cause, fix it once there: it returns only after the app's writes are server-confirmed.
2. For each waived test listed above, read it and fix it if it has this or a similarly clear test-side race. A test whose race you can't identify stays as it is; list it in the report with what you checked.
3. Don't change what any test asserts. No new `waitForTimeout`; use `expect.poll` or web-first assertions.

Done when: `npm test` passes, and `npx playwright test --list` lists the same number of tests. The controller then runs both files on webkit several times, and the full suite.
